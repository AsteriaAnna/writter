# 第一部分：代码格式与交付规则

版本：GREEN / 01 v0.3，2026-11-24。风格名称按原讨论为“新粗野主义 × 瑞士国际主义（Swiss Style）”；“瑞典国际主义”在本轮按同一意图处理。

本文件定义代码约定与检查方法，不宣称消除所有微信客户端差异。用户报告旧版在手机不可见，根因尚未从微信保存后的 HTML 定位。结构检查、模拟复制、普通网页显示、微信保存、手机端是五种不同证据。

## 1. 规则等级与来源

| 标记 | 含义 | 如何处理 |
|---|---|---|
| 结构规范资料 | 来自 wechatjs 的排版结构规范 | 按具体错误场景检查，不能扩展成全标签禁令 |
| 导出共性 | 多个开源工具采用的处理 | 在本库固定执行，不声称是平台完整白名单 |
| 主题约定 | 本库为统一设计而选择 | 对全部组件一致执行，不能作为微信违规结论 |
| 实验项 | 特定 SVG 动画或跨端行为待实测 | 保留组件和设计，明确标注；不以网页正常代替手机验收 |

## 2. 各个环节的要求与禁忌

| 环节 | 必须做 | 避免什么 | 应检查的结果 |
|---|---|---|---|
| 内容输入 | 普通文字 HTML 转义；标题、引用、列表按含义选模板；代码保留原始半角字符和空格 | 把用户文字当 HTML 执行；为凑卡片改事实、删段落或编造引语 | 标题层级、段落、数字、来源与原稿相符 |
| 模板实现 | 完整标签、行内 style；普通文本 leaf 包裹；leaf 只包行内内容；SVG text 单独处理 | p/section/table 放进 leaf；跨标签错闭合；依赖自定义 class 和 CSS 变量 | HTML 结构及 SVG XML 能正确解析 |
| 浏览器预览 | 工具栏、代码展示、按钮、JS 留在正文外；静态图片是示意素材时明确标注 | 让预览 CSS 才能撑开正文；用预览 JS 代替真正 SVG 动画 | 单个组件脱离工具壳仍有完整 inline 样式 |
| 复制 | 写入 text/html 与 text/plain；复制组件根节点而不是整页；失败要显示手动选择提示 | 复制 Markdown 围栏、HTML 源码、按钮和脚本；纯文本复制后宣称样式已复制 | 剪贴板 HTML 只含目标组件；图片异常只影响相关组件 |
| 图片交付 | src 与 data-w 随真实素材更新；图片必须成功加载；最终使用微信支持的素材处理方式 | 把本机路径、blob URL、示例 data URI 当成发布图片；照抄别人的素材地址 | 微信保存后的 img 与图片可见性单独检查 |
| 微信粘贴与保存 | 粘到正文，等待图片处理，保存并重新打开；核对过滤后的结构 | F12 改 DOM 后未保存就算完成；某个插件有源码导入就假定后台原生具备同功能 | 字、图、表格、交互均保留 |
| 手机阅读 | 检查窄屏、字体、字号、溢出、深色模式和点击／滑动 | 手机宽度模拟＝真机通过；PC 不动＝手机不支持；只有一个主题通过就全库通过 | 每组件每通道记录具体客户端与结果 |

复制和 API 草稿是不同通道。本文没有实现图片上传、公众号鉴权或 API 发布，不把浏览器复制当成完整发布闭环。

## 3. HTML、CSS 与文字

- 最终正文不依赖 script、on*、外部样式、@media、@keyframes、CSS 变量、表单或 iframe。预览壳可用脚本处理本地复制，脚本不进入正文。
- 使用 section、p、span、strong、br、img、表格及明确标识的 svg；section 是本库约定，不称 div 一律违法。普通文字用 leaf 是保守策略，不称缺少 leaf 已被证明是手机空白原因。
- 不在普通文本上设置 height:0、固定裁剪高度、line-height:0 或透明度 0。图片无缝拼接与 SVG 热区属于不同情况，分别检查。
- 一般正文自然换行。标题允许换行，不靠 nbps/空格排多列；长 URL 单独 break-all，正文不全文 break-all。内容太长先选其它展示变体，不自动删除文字。
- 不把字号、英文装饰频次、直角当成官方强制要求。正文不逐段自定义字体。代码使用 monospace 是明确的功能例外；其余 HTML 与 SVG 继承同一系统无衬线字体环境。
- 代码先转义 & < >，行内源字符串保留半角引号、空格、换行。代码块每行一个 p、white-space:pre-wrap + overflow-wrap:anywhere；复制出来后核对文本。不能用全角空格伪装真实代码缩进。
- 不故意累积重复嵌套。规范中的深层检查针对冗余链，不能简单宣称“达到 15 层就删除全部”。

## 4. 双栏、矩阵与图片

- 保留双栏与矩阵，采用 table-layout:fixed、百分比列宽、内边距与明确的行高。双栏正文保持 14px 以上；长说明换到 C26 上下对照，由作者选择，不能静默替换。
- 真实数据表使用表格结构，首行明确表头；不将复杂多列表强挤到 320px。要横滚时用明确 overflow-x:auto 的容器，提示可滑动。
- 普通图片用 max-width:100%;height:auto;display:block，小图保留自然尺寸；满宽海报才 width:100%。外框、编号、图注仍是 HTML，不把纯文字全部栅格化。
- 图注无内容就省略，不凭空编造。data-w 是图片原始像素宽度，与显示宽度不同。
- 滑动图集采用原生横向滚动，不能宣称自动轮播；GIF、视频、点击换图分别标记，不能混称动效。
- 组件模板的 `{{IMAGE_URL}}` 是待绑定参数，不可复制发布；样本册使用自包含测试图片只供看布局。输入真实 HTTPS 素材并加载成功后，才能复制该图片组件。

## 5. SVG 交互

- SVG 与 HTML 分开校验。SVG text 不插 HTML leaf，不依赖 foreignObject、defs、marker 或 url(#id) 来显示必要文字和箭头。
- 新增 SVG 使用属性级 SMIL，优先从 opacity、stroke-dashoffset 等已列项目经验中选择，使用 click 触发。禁止用预览 JS 才能工作的假动效。
- 原 I01/I02 的动画改变 viewBox，未出现在 doocs 当前所列动画属性中，因此单独标实验项并保留原外观与行为，不假定其必定被过滤，也不把改动初始 viewBox 等同于 viewBox 动画。
- 原 I01/I02 仍是一次展开，不可回缩；不写成“支持展开回缩”。新增 I03 为固定画板点击揭晓，I04 为固定画板点击描边生长。固定画板不承诺推进文档高度。
- SVG 文字须按可用宽度分行；当文案、字体、素材改变，重新检查坐标、热区、初始状态、终态与后续正文。对 SVG 的尺寸策略不能机械套用普通图片策略。
- 原动画若无法在微信保存，应修该组件并提供经用户认可的替代实现；不得直接删除动效或默认把它静态化。

## 6. 全库统一视觉规则

| 项目 | 统一定义 |
|---|---|
| 主色 | 墨绿 #123a2c；主文字／结构线 #111111 |
| 强调 | 荧光绿 #c6ff00，用于索引、少量高亮和动作提示，不大面积铺正文 |
| 底色 | 纸白 #f7f7f0，次级纸灰 #f0f0e9；说明 #555952；深底辅文 #d2d8d0；墨绿细线 #487061 |
| 字体 | 同一系统无衬线环境；HTML 不逐组件写 font-family，SVG text 也继承；代码 monospace 例外 |
| 字重 | 正文 400，标题与索引 700／900；字体端不支持 900 时不假定可精确复现 |
| 字级 | 元信息 12px、辅助 14px、正文 16px、小标题 19px、章标题 24px、数据 32px；原封面 52px 是品牌展示例外 |
| 几何 | 0 圆角，2px 基础描边，3px 章节线，6px 结构强调；避免无关彩色胶囊、玻璃渐变、阴影装饰 |
| 对齐 | 左对齐、明确栅格，双栏比例和边界可辨；必要时短编号独立列 |
| 间距 | 组件内部以 8/12/16/20/24px 为主。组件导出自带完整背景与左右安全边距，不再套多重文章 padding |

“瑞士”在这里指网格、层级和克制对齐，“新粗野主义”体现在直角、粗线、强对比；不能仅换成绿色就称同风格。

## 7. 导出及验收边界

样本册显示所有组件，不把它们拼成一篇推荐文章；每个组件可单独复制，不连带说明文字和工具栏。普通组件、原 SVG 实验项、新 SVG 实验项的状态分别展示。

本库验证器检查模板结构、风格色板、字体例外、图片参数、leaf、SVG 属性风险和复制隔离；它不是微信官方检测器。输出检查结果不得自动写“公众号已验证”。

验收顺序：源码检查 → 浏览器实际渲染／复制 → 微信保存重开 → 手机浅色／深色／交互。未执行的项目保持待验证。本轮会记录实际检查结果，不把代码规则当作全部已兼容的保证。
