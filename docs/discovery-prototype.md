# 发现选题交互原型

日期：2026-10-06。依据：[上游数据研究](upstream-data-integration.md)。可编辑原型源码：[prototypes/discovery-preview.html](prototypes/discovery-preview.html)，为内嵌预览片段，非线上应用入口。

## 本轮可体验的动作

- 当前热点与更多资讯切换；已按用户反馈移除搜索框。热点沿用上游排名，每页 5 条，整页滚动，不设置列表内滚动。
- 查看题材的来源入口，区分事件更新与首次收录。
- 可选记录想讲的点，再选定题材；返回时保留想法。
- 多选形成独立写作交接卡，可移除或返回资料详情。

使用研究时保存的 AIHOT 全部 10 个热点与 Aggregator 两条资讯，明确为 2026-10-06 快照。无在线请求，不调用模型，不创建云端项目。正文里的概要是选题预览说明；原文事实尚未核验。进入写作后只展示交接边界，没有假装生成正文。

## 交互取舍与待讨论

选题列表先提供足够了解题材的信息，不先要求用户检测或等模型。资料详情在同一工作区打开，返回列表保留选题、想法与当前页码。选题想法选填：事件文章允许先讲清事情，不强制填写个人观点。

当前热点保留上游排名及来源数；补充资讯无摘要和热度时不伪造，也不增加空占位。多选保持独立文章，不自动融合。首版全量列表、时间范围与来源筛选应等真实适配后接入，本原型没有伪造能搜索全网的功能。

本轮重点观察：卡片信息够不够选题，打开资料/返回/选定是否顺手，多选交接是否清楚。绿色米色是视觉方向演示，不代表最终公众号排版已定稿。写作工作台与发布准备尚未实现为可点击页面。

## 验证与状态

真实原型脚本在 happy-dom 完成交互冒烟：初始列表、详情、选择、想法保留、视图切换、独立交接；更新后验证移除搜索、10 条分两页、排名顺序、返回页码与跨页多选。该验证不等于真实浏览器视觉或手机体验通过。

仅交付设计原型和接续记录，线上功能、鉴权、数据库、PR #2 与云环境均未修改。下一项：结合实际操作反馈确定发现选题交互，再设计文章类型、骨架与可编辑要点的工作台；尚未冻结后续写作机制。

## 用户反馈与本次修订

用户认为按序浏览已足够，关键词匹配未必有效，因此移除搜索。两条示例无法说明长列表体验，因此扩到真实快照全部 10 条；采用紧凑列表，每页 5 条，不设内嵌滚动区，详情返回保留页码。分页是待体验方案，尚未认定优于连续滚动，也未验收真实浏览器滚动位置恢复。后续接入 API 时区分上游游标分页与此处本地展示分页。
