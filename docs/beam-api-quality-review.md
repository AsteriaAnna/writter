## 实际执行

1. `/models` HTTP 200，返回 flash 与 pro。
2. 真实生成一次初稿，再独立请求一次审校，结果 needs_revision。
3. 针对正文与审校误判请求修稿，返回的 coverage 元数据未通过原校验，稿件被拒收；该次响应未保留，不能展示或假装完整验收通过。
4. 修正非关键元数据处理后，重新请求修稿与审校：修稿约 26.2 秒，审校约 7.6 秒（客户端调用计时），仍为 needs_revision。

共 5 次模型请求，不含 models 查询。没有继续自动循环。未记录 token 用量或实际账单，不能推算本次费用。

不能凭这篇直接断定“模型性能差是唯一原因”。规则、大纲、资料取舍和审校机制也影响成品；个人风格尚无样稿。此轮证明存在模型遵循与审校质量问题，但未做公平的跨模型比较。

## 审校中的两类实际误判

第一次把“三分之一到四分之一”判作错误，建议却又包含等价写法；这是自相矛盾的审校，不能照单改成含混的“少几倍”。修订采用不依赖该英语倍数歧义的概括，并保留官方归因。

第二次把没有介绍 Reflection 团队背景判为 blocking facts。补背景可以是阅读建议，但没有证明正文事实错误。其文风建议把“不是…而是…”换成“而非”，也是同类结构的替换，并未解决用户要求避免机械句式的问题。

因此模型问题列表应是建议与待核对证据，不是自动删除/改写事实的命令。严重问题要指明具体错误命题、来源冲突或证据越界；省略可选背景、次要细节、所有比较对象不得自动当作严重事实错误。

## 本轮机制修正

`writing-policy.js` 更新为 v1.1：明确算术等价不当作事实错误、未读取独立验证不等于全网没有验证、严重事实问题需具体解释、背景缺失与文风偏好合理定级。修订产物记录的是执行当时 v1 标记；v1.1 的进一步审校定级规则尚未重新实跑，避免将后续规则算作已验收。

coverage 不合格式时清空不可信覆盖信息并附 metadataWarnings，保留合法正文、继续独立审校；不让辅助元数据吞掉用户稿件，也不宣称正文一定覆盖全部要点。新增相应用例，专项测试 5/5 通过。
