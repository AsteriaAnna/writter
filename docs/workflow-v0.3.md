# Writter 主流程改造 v0.3

基线：b90d5636c7e7f5443a198def77d5e7e8b7041399。

## 本轮产品约束

唯一固定主流程：选择热点 → 检测来源 → 策划 → 自然语言调整 → 确认 → 生成正文 → 正文复查 → 确定性排版 → 预览。保留当前账号登录，不新增账号体系。现有页面和结构可调整。

## 底层变更

- schemaVersion=2，在原 PostgreSQL data JSON 中增加 workflow，保持 projects 表和 owner_id/revision 条件更新。无需 SQL 迁移。旧文章保留，但首次使用新生成流程需要重新检测、确认策划。
- documents 保存实际读取的 URL、正文摘录和时间；claims 附 sourceId 与原文 quote；服务端校验引用来源和逐字引用。引用存在不等于事实为真，界面始终说明核验范围。
- 当前来源检测只读取选题原链接和最多四个补充链接，不执行全网检索。AIHOT 独立接口仍未接入；不要把基础来源检测宣称为完整多源联网核验。
- approval 保存确认时的 plan/documents/claims 快照；正文从快照生成。修改策划或证据让下游失效，正文改动让复查和排版失效。
- tasks.start 保存 pending 任务，tasks.run 通过 revision 条件更新认领后执行。任务结果只有在同一版本仍有效时写入；重复 run 不重复调用模型。
- 正文 AI 复查绑定精确正文内容；有 blocking 问题不允许排版。它不是独立人工核验，也不保证无事实错误。
- Markdown、标题和链接经过确定性转义与受控渲染，模型不输出最终 HTML。纯复制页使用已经保存的 output.html。

## 任务生命周期限制

任务执行由浏览器发起的第二个云函数请求承载，不是常驻队列工作器。页面恢复后会读取进度并执行 pending 任务；正在执行的任务依赖云函数实际生命周期。过期后允许重新发起，无法保证供应商调用在基础设施中断时 exactly-once。后续如需要无人值守或批量生成，再接入真实队列/独立工作器。

## UI 变更

策划台展示来源证据、引用、提醒和 AI 策划，支持自然语言调整与直接修改。正文页展示生成、复查、配图建议与预览。去掉人工勾选充当检测的主要交互。保持当前项目；内部阶段改为中文；移除产品页面的 UID、地域状态。输入立即在当前账号的浏览器中暂存，一秒空闲后保存云端；失败保留暂存。离开页面保留暂存，下次进入恢复，刷新时提示未保存内容。

## 云端配置与部署（交给本地 Codex）

1. 合并本分支后 npm ci；npm test；npm run check；npm run build。
2. 在 writter-api 云函数环境变量配置 WRITTER_AI_KEY，密钥仅存云端，不放仓库、前端或聊天。
3. WRITTER_AI_BASE_URL=https://api.deepseek.com；WRITTER_AI_MODEL=deepseek-flash。默认关闭 thinking，JSON 输出上限 6000 tokens；没有自动升级高价模型。
4. 保留 WRITTER_ALLOWED_UIDS 和 PostgreSQL 配置，不用新建表，也不改成公开数据库。
5. 云函数 timeout 必须从 30 秒调整为 180 秒。客户端 140 秒；模型请求 100 秒；来源整体 20 秒。cloudbaserc.json 已更新，部署后核对控制台实际值。
6. 部署 dist/writter-api（index.main），并将 dist/hosting 全量部署静态站点。不要只更新前端；它依赖 capabilities、tasks.start、tasks.run 新接口。
7. 不要执行凭据轮换或清空原数据。

## 验收

- 有效原始来源：检测取得真实正文和逐字证据，产生策划；自然语言调整后重新确认。
- 生成正文，复查，与证据不一致的内容能定位；修正后重新复查再排版。
- 故意在任务执行中保存新策划，确认晚到结果没有覆盖新版本。
- 页面刷新后的 pending/running/failed 任务能读取状态；超时后可重试。
- 切换页面、版本冲突和刷新不丢当前浏览器暂存。
- 无密钥、来源不可读、模型无效 JSON 均应提示失败，不能伪装成成功。
- 手机宽度检查策划、正文、操作栏和纯复制页，再到微信公众号编辑器实测粘贴。
